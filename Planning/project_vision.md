# **Project Vision Document**

## **Project Name:** To-Create  
**Project Type:** Project Management To-Do App  

---

## **1. Problem Statement**  
In academic and student association environments, project management often relies on fragmented tools (e.g., emails, chat apps, or spreadsheets), leading to disorganized workflows, missed deadlines, and unclear task ownership. There is a need for a **lightweight, role-based web application** that enables student teams to create, prioritize, and track tasks aligned with specific project objectives. The current lack of a centralized system results in inefficiencies, poor accountability, and reduced productivity in collaborative student projects.  

**To-Create** addresses this by providing a **simple, intuitive task management platform** that organizes tasks based on project objectives and user roles within production teams.  

---

## **2. Project Objectives**  
- **Develop a lightweight web application** that enables the production team to organize, prioritize, and monitor professional and personal tasks through a simple and intuitive interface.  
- **Implement role-based task generation** using project objectives and user roles in the production team to create personalized to-do lists.  
- **Ensure user-friendly design** with responsive interfaces accessible on desktops and mobile devices.  
- **Facilitate efficient project management** for student associations and academic teams through task organization, role management, and filtering.  

---

## **3. Target Users**  
### **Stakeholders:**  
- **Client:**  
  - *University Student Association* – Requires a centralized platform to manage student-led projects, events, and initiatives.  

- **End Users:**  
  - *Students* – Members of student associations or academic teams who need to organize, track, and complete tasks collaboratively.  

- **Development Team:**  
  - *Four Members* – Responsible for designing, developing, testing, and deploying the web application.  

### **User Roles in the System:**  
- **Administrator** – Manages users, projects, and roles.  
- **Project Manager** – Creates projects, assigns roles, and oversees task generation.  
- **Team Member** – Creates, edits, deletes, and filters tasks within assigned projects.  

---

## **4. User Stories**
1. As a Project Manager, I want to create a new project so that my student team can organize tasks in one place.
2. As an Administrator, I want to add and remove users so that only authorized team members can access the application.
3. As a Project Manager, I want to assign roles to team members so that each person has the correct permissions.
4. As a Team Member, I want to view tasks assigned to my role so that I can focus on my own responsibilities.
5. As a Team Member, I want to create a new task so that I can capture work items that need to be completed.
6. As a Team Member, I want to edit task details so that I can update progress, priority, or due dates.
7. As a Team Member, I want to delete tasks that are no longer needed so that the project board stays relevant.
8. As a Project Manager, I want the system to generate tasks based on project objectives so that task creation is faster and more aligned.
9. As a Team Member, I want to filter tasks by status, priority, or project so that I can focus on what matters most.
10. As a Project Manager, I want to view all projects in one dashboard so that I can oversee the entire workload.
11. As an Administrator, I want to manage user roles and permissions so that I can enforce role-based access control.
12. As a Team Member, I want to mark tasks as complete so that my progress is visible to the rest of the team.
13. As a Project Manager, I want to search for projects or tasks quickly so that I can find items without wasting time.
14. As a Team Member, I want a responsive interface so that I can manage tasks from both desktop and mobile devices.
15. As an Administrator, I want the application to provide a simple, intuitive layout so that new users can learn it quickly.
16. As a Project Manager, I want to set project objectives so that generated tasks reflect the goals of the team.
17. As a Team Member, I want to receive clear task details so that I understand what needs to be done.

---

## **5. Scope**
   - Users can create tasks manually.  
   - Users can edit tasks.  
   - Users can delete tasks.  
   - Users can filter tasks (e.g., by status, priority, or project).  
3. **User Experience**  
   - Responsive interface (desktop and mobile).  
   - User-friendly experience with intuitive navigation.  

### **Out-of-Scope (Future Enhancements):**  
- Integration with third-party tools (e.g., Google Calendar, Slack).  
- Real-time collaboration features (e.g., live chat or video calls).  
- Advanced analytics dashboards (e.g., productivity metrics).  
- Mobile app versions (initially web-only).  

---

## **5. Success Criteria**  
- Users can successfully create, manage, and complete tasks within a project.  
- Task generation aligns with project objectives and user roles.  
- The application is accessible and responsive across devices.  
- The platform reduces task duplication and improves project visibility.  

---

## **6. Constraints & Assumptions**  
- **Constraints:**  
  - Limited to a web-based application (no native mobile app).  
  - Four-member development team with a 3-day project duration (per exam guidelines).  
- **Assumptions:**  
  - Users have basic web literacy.  
  - The university provides basic infrastructure for hosting (or development uses local hosting).  

---

## **7. Deliverables**  
- Functional web application with core features.  
- Project report and PowerPoint presentation.  
- Oral presentation with demonstration.  

---

## **8. Agile Alignment**  
- **Framework:** Scrum (or Kanban, depending on team preference).  
- **Sprint Duration:** 1–2 days (aligned with 3-day project timeframe).  
- **Key Practices:**  
  - Daily standups to track progress.  
  - Sprint review at the end of each iteration.  
  - Retrospectives to improve workflows.
